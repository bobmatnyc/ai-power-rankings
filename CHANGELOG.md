# Changelog

All notable changes to this project will be documented in this file.

**Public feed rule (owner ruling 2026-10-26, #303).** This file is the developer record and may hold any change. The public What's New feed and `/api/changelog` list only content or feature changes a reader sees. A bullet is public only when it starts with the conventional-commit type `feat`, `fix` or `data`; a bullet with any other type (`chore`, `refactor`, `test`, `ci`, `docs`) or with no type stays out (`PUBLIC_TYPES` in `lib/data/changelog-generator.ts`). Example public: `feat(tools): tool pages list linked models and harnesses`. Example not public: `chore(logos): vendor-logo infrastructure`. Infrastructure, lint, tests and refactors take a non-public type even when they are not a bug fix.

## [Unreleased]

### Security
- fix(auth): the middleware's 401 for an anonymous protected API request (`/api/admin/*`, `/api/data/*`, `/api/ai/*`) carries `Cache-Control: no-store`. It is returned before any route runs, so a route's own no-store wrapper never applied and the response went out cacheable. Tests: `tests/unit/middleware-401-no-store-325.test.ts` (#325)
- fix(auth): harden auth routing for admin and dashboard paths. The middleware `config.matcher` now includes `/:locale/admin(.*)` and `/:locale/dashboard(.*)`, matching the page entries of `PROTECTED_ROUTE_PATTERNS`, so every request under those trees gets the middleware's sign-in check. The admin and dashboard trees also have server layouts that check the session through `requireAuth()` (Clerk `auth()`) and redirect a signed-out request to `/<locale>/sign-in` with the tree root as `redirect_url` (`lib/protected-page-guard.ts`). Tests: `tests/unit/middleware-matcher-protected-trees.test.ts`, `tests/unit/protected-page-guard.test.ts`
- fix(auth): the middleware classifies percent-encoded paths. `routeAccess()` matched the raw pathname, which keeps percent escapes, so `/en/%61dmin` and `/api/%61dmin/x` classed as unprotected and skipped the sign-in check; only the router's 404 kept them from serving. A path is now protected when its raw form or its once-decoded form (`decodeURIComponent`, as Next's route lookup does) is protected, and an anonymous request whose raw or decoded path is under `/api/` gets 401. A path is decoded once only, so `/en/%2561dmin` stays unprotected and the router answers 404; a malformed escape such as `%E0%A4%A` classifies the raw path and never throws. Public paths, including `/api/cron/*`, keep their class, and decoding never makes a path public. Tests: `tests/unit/route-access-encoded-228.test.ts` (#228)
- fix(auth): enforce admin authentication on admin tool-scoring API routes. `/api/admin/tools/scoring` (GET/POST/PUT) and `/api/admin/tools/scoring/recalculate` (POST) now call `requireAdmin()` from `lib/api-auth.ts` before any database access: 401 without a session, 403 for a non-admin. The same check replaces the sign-in-only check in the other `/api/admin/*` handlers that had one (articles by id, article recalculate and ingest, articles-v2, db-status, db-status-v2, rankings rollback and versions, SEO sitemap submission, image upload) and is added to the stub handlers that had none. The middleware now checks protected routes (`/:locale/admin`, `/:locale/dashboard`, `/api/admin`) before public ones, anchors public page patterns to a configured locale segment (`lib/route-access.ts`), and answers an anonymous protected `/api/*` request with a 401 JSON body instead of a sign-in redirect
- fix(auth): `/api/data/db-status` and `/api/data/articles` now verify the Clerk session through `requireAdmin()` instead of checking that a session cookie is present. An anonymous caller gets 401 and a signed-in non-admin gets 403, with no database details in either response. `lib/manual-auth.ts` and the unused `lib/server-actions/admin-actions.ts`, its only other caller, are removed. The what's-new summary regeneration POST and `/api/ai/analyze-news` also require an admin through `requireAdmin()`. Tests: `tests/unit/auth-hardening.test.ts`.
- fix(auth): `requireAdmin()` and `requireAuth()` in `lib/api-auth.ts` fail closed when `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` or `CLERK_SECRET_KEY` is missing in a production-like environment (`NODE_ENV=production`, or `VERCEL_ENV` of `production` or `preview`): they return 503 and never a mock user, and `NEXT_PUBLIC_DISABLE_AUTH` is ignored there. The mock identities remain for local development only, with a warning. Tests: `tests/unit/api-auth-fail-closed.test.ts`.
- fix(auth): `POST /api/admin/articles/[id]/recalculate` runs `requireAdmin()` before it reads the request body. The middleware answers an anonymous request to a protected API path with 401 regardless of the path's letter case (`/API/admin/...` used to get a sign-in redirect). `tests/unit/middleware-route-access.test.ts` now checks the exported `config.matcher` with Next's `unstable_doesMiddlewareMatch`, including bare `/api/admin`, `.json` and `.png` suffixes, an upper-case path and Clerk sign-in sub-routes.

Generation runs only through the admin POST. `/api/data(.*)` and `/api/ai(.*)` join the middleware's protected routes, so an anonymous request is refused before the handler runs. `/api/data/db-status` reports a masked host (a short first-label prefix plus `***`) instead of the full hostname.
